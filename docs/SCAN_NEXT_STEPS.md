# 下一阶段范围（2026-10-22）

保留任务制和IPv4 TCP 1–65535完整性。当前主线为合理发包速率、现版全流水线耗时与按证据优化；Nuclei漏洞PoC扩展暂缓，不扩大模板或协议执行范围。

## 速率选择

10000 PPS是[已有5台两核Worker、1000IP验证](SCAN_SPEED_VALIDATION.md)采用的配置，不是硬件最大值。当前代码和示例配置仍以5000PPS/4IP为保守回退；已有部署使用10000PPS、同目标共享10000PPS、最多8IP/片。对比前必须读取实际生效任务载荷，不能混用两套配置。

阿里云u1-c1m1.large的官方指标为2核2GiB、内网基准1Gbit/s、收发包30万PPS；规格不是扫描器或公网的稳定吞吐保证。[官方规格](https://help.aliyun.com/zh/ecs/user-guide/general-work-force)同时需要结合[公网带宽限制](https://help.aliyun.com/zh/ecs/user-guide/network-bandwidth)及[实际网络性能验证](https://help.aliyun.com/zh/ecs/user-guide/best-practices-for-testing-network-performance)。

计划阶梯为10000、15000、20000PPS；后两档仍待验证，不作为已通过值。平台当前会将Worker预算钳制到单目标共享上限，所以自建目标的配置实验必须显式记录并核对两项额度。单个目标跨Worker的额度仍共享，不能把节点数当成提高目标总速率的依据。

先用同5台同规格节点、相同自建目标和固定片宽做小样本筛选，再对候选档验证混合流水线和资源余量。依据唯一IP×端口覆盖、已知开放端口召回、发送错误/重试、观察器丢包、真实字节率、CPU/RSS与下游积压选择档位。VPC/VXLAN证据不能替代公网路径证据；1000IP只对有完整收尾预算的关键配置开展。每轮从资源创建到释放不超过1小时，最多10台两核Worker，比较固定5台。

## 时间与质量口径

分别观察端口覆盖完成、基础HTTP结果集就绪、所选全部阶段结束，均从run接受时刻起算。流水线有重叠，不能将阶段时间相加，也不能把两种模式总时间的差值当成某工具执行时间。

基础HTTP队列暂时为空不代表就绪，还要等待会派生HTTP的上游闭合。工作结束与覆盖完整分开；历史缺少可信结束时点时保留未知，不用任意更新时间填补。三阶段的历史时点API/展示目前仍待实现，本轮没有将其写成已完成能力。

复用已有队列、工具资源和执行记录，只补归因所需指标。先解释许可等待、网络请求、本地匹配、启动和回传成本，再修改主要瓶颈；小样本单次配对只报告观察差异，结论依赖小幅变化时才补反序复测。
