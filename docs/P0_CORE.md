# P0 核心扫描闭环

基线：[执行架构v0.5](SCAN_ARCHITECTURE_V2.md)。状态：P0核心路径已部署，并通过本地及阿里云自建隔离目标的真实工具闭环。本页记录实际实现范围；设计中的未完成优化不算已完成能力。

## 执行路径

IP任务保持TCP 1–65535：Masscan完成端口分片并排空结果后，派生Nmap轻量服务识别；HTTP/TLS-Web及未知候选进入独立Web入口。域名/URL直接进入Web，不派生IP全端口扫描。Web响应由有界采集helper交给常驻fingers，产品归一后仅在任务显式开启PoC时选择检查规则。

沿用PG任务、租约、attempt和结果批次凭证。端口区间清单持久化，完成时检查覆盖；未完成attempt的观测不混入最终有效结果。完成快照固定被接受的执行，后续消费不依赖旧租约仍有效。执行错误、部分证据与未命中分开。

## 首版控制

- 维护状态只暂停新认领，保留已有执行；新Agent声明停发确认能力，旧Agent不会收到需要新协议的执行。
- Agent持有本地启动槽再参与端口分片，平台只用真实启动预留计算k。`SCAN_CALIBRATED_PORT_PROFILE`、`SCAN_CALIBRATED_PPS`、`SCAN_CALIBRATED_SYN_RATE`来自同配置实测；空值不假造速率。Worker的`AGENT_SPEC.port_profile`须匹配。
- `SCAN_TARGET_DISCOVERY_PPS`为所有Worker共享的目标额度，默认5000；不因增加节点而自动放大。PPS、服务作业与Web作业预算分开，不宣称所有工具共享严格的应用请求硬限速。
- 未确认停止的额度进入suspect/revoking；云调和只处置本池节点，重复直接查询确认实例消失后释放对应session额度。手动节点无法确认停止时显式阻塞，不自动解冻。
- 取消终止进程组并等待执行器退出，才上报停止确认。云删除请求受理不视为停发证据。
- 重试、恢复窗口与run终结有界；成功/受限/缺口分别记录，排队暂空不等于全任务完成。
- 高开放率仍保留端口发现记录，下游指纹派生保持已有上限。捕获丢包、输出越界、解析失败和缓冲超限均不能封账为完整覆盖。

## 工具与部署

Nmap轻量服务批次最多32个端口，工具执行预算60秒，任务总截止90秒以保留结果回传余量。Nmap使用系统完整包，包含service probes数据；新Agent缺少Nmap时不认领对应服务工作。两个Web helper使用独立Go module，详见 [构建与接口边界](../deploy/WEB_HELPERS.md)。发布脚本构建并打包helper，bootstrap安装Nmap和helper；镜像可预装同样内容。

Web采集采用httpx请求/标题SDK、WappalyzerGo及有界标准库传输层，未调用完整httpx runner；这是为执行固定连接IP、在线解压上限及同连接TLS证据所做的明确适配。fingers只启用被动库，少量同源favicon作为本地步骤；不启用通用主动模板接口或AI。大响应持久化预览带截断/摘要标记，不能充当完整原始报文。

已有PoC范围保持不变。Nuclei只有经过验证的单请求响应profile和本次完整证据同时满足时才报告可证明未命中；多请求未完成证明不足时显示“证据不足”，不通过反复扫描制造阴性。界面支持该状态筛选。
