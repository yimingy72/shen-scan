# 清晰工作台：信息组织与交互

更新：2026-10-17。

工作台围绕「扫描任务 → 原始目标 → 开放端口 / HTTP 端点 → 识别依据」组织。扫描观测是某次任务的发现记录，不直接充当跨任务的资产台账，因此菜单使用“扫描结果”。

| 模块 | 用户首先需要知道什么 | 本版组织 |
| --- | --- | --- |
| 扫描任务 | 扫了哪些目标、进展如何、发现多少 | 名称直接进入该任务结果；并列显示状态、模式、去重目标数、开放端口数、HTTP 端点数、执行步骤 |
| 扫描结果 | 每个 IP 开了什么端口，域名发现什么站点 | 必选一个任务；目标列表汇总端口、服务、产品、页面标题与指纹；展开目标查看端口明细 |
| HTTP 端点 | 哪些页面有响应，是什么技术 | 默认有响应；可切换无响应或全部探测；区分来源目标、最终 URL、实际连接 IP、状态码、标题、Server、CMS/框架 |
| 结果详情 | 指纹从哪里来，能否复核 | 先显示连接和识别信息，再显示识别依据、响应/请求报文；未保存的历史字段明确标注，不生成虚假内容 |
| Workers | 当前容量是否够用，哪些节点需要处理 | 标题与页签共用一行；在线、启动、排空及目标数量共用一条工具栏；默认只看当前节点，已释放节点单独查看 |
| 云账号 | 账号能否连接，配置是否已保存 | 输入型密钥字段、真实身份及查询权限验证、验证成功后保存；保存后返回掩码，不回显密钥 |
| 云资源 | 网络是否就绪，在哪个地域启动 | 地域/可用区与真实 VPC、交换机、安全组、镜像、候选规格；准备网络与启动实例是两个明确操作 |
| 登录 | 如何进入工作台 | 保留现有管理员令牌认证；API 地址收进连接设置；令牌仍只保存在当前标签页会话中 |

## 计数与状态

- 目标按原始输入 IP / 域名归组。URL 保留在 HTTP 结果中，域名的解析 IP 和重定向目标不会变成另外一个被全端口扫描的目标。
- 任务的目标数量按归一化目标去重，CIDR 按实际拆分的 IP 计数；原始输入单独保留在“任务信息”。
- 开放端口只来自端口扫描的发现记录，按任务内目标与端口去重。服务识别、HTTP 响应不会重复增加端口数量。TCP 扫描仍为 1–65535。
- HTTP 端点数量仅统计收到 HTTP 状态码的 URL。一个 URL 在当前执行版本内有多条记录时，优先保留成功收到响应的最新记录；没有响应的探测可以单独查询。
- 展示时只纳入当前 `attempt_no` 的记录，过期重试结果不会混入本次统计。端口摘要最多显示 12 个按钮，完整端口仍可分页查看，不截断存储或扫描范围。
- 没有发现的目标也保留。尚未执行、未执行端口扫描、扫描完成但未发现、失败、取消分别展示；无响应不等于端口关闭。
- SSH 等非 HTTP 端口的 HTTP 探测无响应不等于任务执行失败；“执行失败”筛选使用执行步骤状态，不拿普通探测未响应代替。
- “执行步骤”表示内部扫描与识别步骤数，不用它冒充目标覆盖率。派生服务/HTTP 步骤后分母可能变化。
- Workers 的“在线”包含空闲和扫描中的健康节点；启动中和排空中另列。已释放或离线节点不展示过期指标为实时负载，历史采样只在详情中带时间展示。

## 云配置的真实行为

`GET /api/cloud/aliyun` 读取脱敏配置；`POST /api/cloud/aliyun/verify` 验证账号身份及 ECS、VPC、系统事件查询；`PUT /api/cloud/aliyun` 在验证成功后保存。验证不会创建实例，也不等价于证明所有创建/删除权限。

新凭据使用 AES-GCM 加密后写入 PostgreSQL，解密密钥默认位于控制面 `data/cloud-credentials.key`（0600）。数据库与此密钥应一起纳入受控备份；密钥不返回浏览器。保存配置优先于环境变量，进程重启后继续生效。

修改账号或地域要求 Worker 池已停止且所有已知实例释放确认完毕。更换账号、地域或可用区会解除旧网络绑定，保留旧云资源，随后由“一键准备网络”发现或创建当前范围内的专用资源。已有配置下准备网络会复用专用资源，不自动启动 Worker。

## 结果接口

| 接口 | 用途 |
| --- | --- |
| `GET /api/runs?summary=true` | 列表只取前 2 条原始输入与 `input_count`；任务信息按需调用 `GET /api/runs/{id}` 获取完整输入 |
| `GET /api/runs/{id}/results` | 任务内目标分页与去重统计；支持目标、服务、产品、指纹搜索 |
| `GET /api/runs/{id}/ports?target=...` | 单目标开放端口、服务/产品、关联 HTTP 结果 |
| `GET /api/runs/{id}/http?target=...&status=responded` | HTTP 端点；`target` 可省略，响应筛选支持 `responded` / `no_response` / `all` |
| `GET /api/observations/{id}` | 按需加载完整已存储的识别信息和报文 |
| `GET /api/cloud/aliyun/instances` | 已申请、未注册、运行、排空及已释放实例的持久状态 |

所有接口沿用管理员认证。旧 `/api/assets` 保留兼容，新界面不再把原始观测条数称为资产数。

新 Agent 会附带最多 4096 字节的已读取服务 Banner；旧记录没有此字段时不补造。既有 HTTP 采集上限和截断标志继续保留，详情按真实记录显示。

## 批量任务的进度

任务列表按“已完成目标 / 目标总数”显示进度；派生服务和 HTTP 子任务时，总目标数保持不变，避免内部步骤增加使进度条倒退。内部步骤计数保留在任务详情。Worker 详情列出一个分片内的全部 IP，失败目标展开后显示原因及结果不完整提示。

## 页面性能

任务列表合并重复 SQL 聚合，目标、端口与 HTTP 分页在同一条查询中返回条数和内容，避免两遍汇总。结果仍来自当前执行版本，未引入过期结果缓存。页面只展示摘要，完整原始输入和报文在打开详情时获取。

有活动任务时列表每 10 秒刷新，全部结束后降为 60 秒；已结束任务的目标、端口和 HTTP 结果停止轮询。Workers 页不请求扫描任务列表。隐藏标签页跳过轮询，慢请求完成后再安排下次刷新，避免定时器反复中断尚未完成的请求；手动刷新仍可用。

JS/CSS 在构建时生成 gzip 文件；支持 gzip 的浏览器获取压缩内容，带内容哈希的资源缓存一年，入口 HTML 每次重新验证。发布必须包含构建产物中的 `.gz` 文件；不支持压缩的客户端仍能读取原文件。

## 规则库与 PoC

规则库按 HTTP、端口、PoC 分类。PoC 列表显示关联指纹、请求范围、引擎与级别；空绑定显示“手动指定”。编辑页可以从已知产品选择绑定，也可输入自定义产品名。列表支持筛选导出、跨页勾选导出 / 删除；内置规则也可删除且不会在重启后复活。

创建任务默认关闭只读检查，开启后默认按指纹匹配，选择具体产品规则仍要匹配产品。通用检查须手动选中。结果页把触发指纹与检查证据分别显示，信息级发现不会当作已确认漏洞。

“上游原库”抽屉单独展示 Nuclei catalog，可按用途搜索、查看完整 YAML、来源路径和 metadata，并下载整个 revision。界面明确标注原始执行器未接入；这些条目不混入指纹库 / PoC 执行计数，目录中的 enabled 也不表示可以运行。
