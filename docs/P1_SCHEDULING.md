# P1 共享 HTTP 限速与扫描调度

本文描述代码实现语义；本地夹具的合成耗时不是生产校准，也不是云端性能结论。实际云性能及完整验收证据由对应验收报告记录。

## HTTP 请求共享许可

HTTP采集、图标及已支持PoC中的HTTP/HTTPS请求统一领取许可。Nmap服务探针继续按服务作业额度控制。PostgreSQL 按实际连接 IP 共享每秒10个许可，并按整个集群共享每秒250个许可；不同域名指向同一IP时也共用额度。默认额度由平台设置，增加Worker不扩大额度。已有同目标作业槽继续限制在途工作。

许可接口校验Worker、session、task、attempt、有效执行租约和额度状态，并固定本次执行的域名到连接IP绑定。首次解析仍由经过认证的Agent按现有目标策略完成；预先指定IP必须精确匹配。每个任务使用串行递增请求编号，重放不重复扣除、不延长有效期，旧编号和失效执行拒绝。等待在事务外进行，数据库只保留每任务的最新凭证和有界清理的IP桶。

许可发放的burst为1、有效期至多500毫秒。Agent在连接/TLS完成后、写HTTP请求前申请，使用单调时间扣除通信耗时；过期、取消和控制面失败时关闭连接。由于通信和调度延迟，请求实际开始可能聚集：有效期内每IP最多约6个许可可能聚集使用，不能把发放速率解释为网络任意一秒精确到达10次。控制状态公开标记为 `cooperative_request_admission`。

本地CONNECT代理终止客户端TLS，逐个解析HTTP/1请求、校验范围后向原目标转发；CONNECT连接本身不抵扣一次HTTP请求。没有启用不透明隧道或HTTP/2旁路。原有Web helper继续直接连接固定目标，保留实际同连接TLS证据；每次请求通过带独立随机令牌的回环回调向Agent申请许可，工具不获得控制凭据。

新HTTP/PoC任务只派给声明 `supports_http_request_budget` 的Agent；旧Agent仍可处理兼容的端口/服务任务。维护模式只阻止新领取，已在执行的工作可继续申请许可；取消、额度冻结和真正停止执行会拒绝新许可。

## 工具进程复用和逐模板结果

Web helper使用有界JSONL协议常驻复用，逐入口具有独立ID、截止与回调令牌，只缓存一个有界CFF解析结果。取消、进程错误或返回身份不符时，先终止并等待进程退出，再供后续入口创建新进程；Agent关闭时回收子进程。fingers原有被动库matcher继续复用。

同一入口可把最多4条符合 `nuclei-3.11.1-single-http-batch-v1` 的原始模板装入一个Nuclei进程。要求3.11.1引擎、每模板单个请求和单个matcher、唯一模板ID、原始SHA一致，关闭引擎聚类；其他模板保留单模板路径。不同入口的模板不会取并集。

每条模板的事件需与ID、文件、请求计划和真实上游交换凭证对应。完整且可证明的matched/not_matched结果到达控制面后独立保存不可变凭证；错误、缺失或不完整事件没有阴性凭证。重派只下发尚无凭证的模板，批次最终覆盖必须逐模板核对。代理拒绝产生的502不能充当目标响应。新批次仅给声明对应能力的Agent；PoC仍默认关闭、任务显式开启并按产品匹配。

## 成本与未来批次

平台只为新工作调整 IP 种子和服务装箱大小，不迁移已有端点工作；从未认领的服务批次可在容量内只追加新工作，详见下文。近24小时最多32个首尝试样本按时间平滑，每次变化有界，最终受现有硬上限约束；不足三份样本只能收紧，慢样本、失败和不完整样本会收紧并禁止该窗口内恢复放大。

IP批次样本只使用当前PPS、15秒等待、TCP 1–65535完整范围；端口区间任务不能以“一份IP工作”混入样本。服务样本只使用当前 `nmap-light-v1` profile。历史检索有对应时间排序索引，查询不以最新心跳节点数量充当容量。

异构成本只使用同一Worker/session在相同PPS和等待配置下、完整完成的首尝试。至少四份且工作量最大不少于最小两倍时才拟合每端口成本和固定开销；固定开销包含等待、启动、结果排空与回传，使用保守成本置信界。失败后只使用失败之后的新完整样本，不能退回更乐观的旧配置基准。观测不足时仅允许明确匹配的已有校准基准，否则单片回退；不从开放端口数量或配置PPS虚构有效覆盖速率。

规划只使用仍有效、Worker/session匹配且持有目标额度的启动预留，按逐片 `固定开销 + 区间大小/有效成本速率` 预测，并计入收集窗口。候选方案逐一满足2秒/15%收益门槛后，在近最优方案中选最少节点；区间至少4096端口。每个实际选中进程保留独立PPS份额，节点增加不扩大目标总PPS。完整区间清单仍先原子持久化，随后认领时激活额度，重试保持原范围。

## 独立接受的阳性端口凭证

这是对P0“未完成attempt观测只作历史”的一项明确例外，范围仅限成功接收的端口阳性记录：

1. 批次先通过当前任务、Worker/session、attempt、有效lease和全部范围校验；部分非法批次整体拒绝。
2. 同一事务保存原批次摘要、原始观察、唯一 `run/IP/TCP-port` 阳性凭证及服务任务。凭证保留来源任务、attempt、batch_seq、完整摘要和观察ID。
3. 阳性凭证证明在当时有效执行中接收过开放端口；它不证明整个区间已扫描，也不把未返回端口解释为关闭。
4. 后续source失败、超时或重试保留该凭证及其独立下游工作。其他类型的未完成attempt观测仍不进入最终有效视图。历史版本尚未接受的未完成端口观察不被迁移为新凭证。
5. 已提交批次可按原摘要幂等重放，重放不产生新凭证或派生。变更摘要冲突；旧attempt的新批次被拒绝。

服务工作用稳定 `run/IP/TCP-port/service-profile` 绑定去重；不同源attempt的同一端点不会重新占用下游预算。早到批次、完成补派和重试共用每目标1024个端点的指纹预算；全部端口阳性证据继续保留。逻辑端点工作及其独立阳性凭证保持不变；从未认领的queued/attempt 0服务批次可接收新增工作。同run、IP、服务profile、HTTP开关且仍有容量的批次，持行锁追加新端点，填至当前自适应上限（最多32个）；没有容量才建立新批次，不增加等待窗口。已认领、曾启动、重试或完成的批次绝不追加。批次source字段仅保留首次来源追踪，不代表整批所有端点的来源；每端点阳性凭证才是各自的来源依据。提前派生的时延收益与额外进程开销一起实测。后续服务工作的自身重试仍沿用原有有界恢复机制。

目标、端口、资产及run统计同时识别独立阳性凭证和正常完成的结果。端口列表提供阳性凭证ID和观察ID，观察详情返回完整来源与批次摘要。目标结果的 `port_coverage` 独立显示 `unconfirmed/partial/complete`；只有原始完整清单中的全部端口任务完成且覆盖为complete才显示完整。来源失败但有已接受阳性时仍显示这些端口及partial覆盖，run须等待全部下游终结后按现有规则结束为partial。

表结构与一次性既有服务绑定回填由 `initializeEarlyPorts` 完成，随目标索引初始化运行，不改并行开发中的Server初始化代码。没有增加递归任务依赖、通用DAG或跨任务资产库。

## 运维可见性

Masscan在Linux安静网卡上的抓包读取已改为非阻塞，并在读空时使用最多100毫秒的poll等待，保证不依赖背景报文也能检查退出标志；有缓存报文时连续排空。行式输出逐条刷新，写入或刷新失败返回非零状态，保证提前派生能在进程结束前收到真实结果。固定上游版本、32MiB接收缓冲、抓包丢失统计和完整对应源码一同发布。该修复不更改发包速率或端口范围，见[Masscan源码说明](../deploy/masscan/SOURCE.md)。

「Workers → 调度策略」展示HTTP共享额度、阶段排队/执行数、最长等待、未来IP/服务批次上限和样本依据。端口结果可查看独立接收凭证，全端口覆盖未完成时明确显示；任务仍按原有任务制查看结果。
