# 调度、并发与结果完整性

本文描述当前源码策略，不代表已经完成大规模公网容量验收。批量扫描提速对照工作已停止，仍需后续验证。

## 容量与分片

用户设置 Worker 池目标数量。创建任务时，优先用存活 Worker 数估算分片；没有存活节点时采用池目标数量，最低按 1 台计算。节点自行认领，失联分片按租约重派。

IPv4 输入展开、去重并排序。默认发包预算 5000 PPS，默认片宽上限 4；分别可通过 `SCAN_PORT_RATE_PPS`（1000–20000）与 `SCAN_PORT_SHARD_MAX`（1–16）调整，非法值回到默认值。

有效片宽上限为：

```text
min(配置片宽, max(1, floor((180 - 15 - 30) × PPS / (2 × 65535))))
```

其中 15 秒是收包等待，30 秒为回传等工作预留；两倍包量用于估算响应场景下的探针和清理包预算。这只是分片约束，不是实际耗时或网络无丢包的保证。

在有效片宽内，平台尽量生成至少一片 / Worker，并让片宽相差不超过 1。大任务使用满足上限所需的最少片数，减少重复等待；小任务尽量一波铺开。每个 IP 仍扫描 **TCP 1–65535**。

## 执行与公平性

默认每个 Agent 17 个任务槽，其中最多 1 个端口扫描、16 个服务 / HTTP 任务。认领优先检查端口工作，指纹任务不能占用预留的端口槽；显式配置为单任务 Agent 时，两类工作交替优先，避免饥饿。

控制面按任务轮转；在选定任务内优先重派过期租约或主动释放的分片，再按目标游标取新工作。`SKIP LOCKED` 避免阻塞等待已锁定任务。同一 Worker 对同一目标最多同时执行一个服务或 HTTP 子任务，限制热点目标占用。

全局端点并发默认 16，服务单任务最多 8，HTTP 单任务最多 2。服务按 32 个端点分片，单端点最多 5 秒；HTTP 按 8 个端点分片，单端点总预算最多 12 秒。

自动 HTTP / HTTPS 探测共用一个端点截止时间，首个协议最多占一半；显式 URL 使用完整预算。已收到状态码的响应即使正文超时也保留证据，不再盲目切换协议覆盖。

## 捕获与回传

使用固定 Masscan 1.3.2 接收修复：snaplen 2048 字节、捕获缓冲 32 MiB、退出时输出捕获计数。发现捕获丢包时任务明确失败并保留已收到的观测，不将不完整结果标成成功。正式发布使用随包扫描器，详见 [构建说明](../deploy/masscan/README.md)。

Masscan 的原始行式输出写入权限为 0600 的临时普通文件，Agent 同时跟随读取。网络上传变慢时，读取位置可以落后，避免上传反压直接堵住扫描器接收线程。进程结束后继续读完尾部，排空结果队列，再提交完成确认。

临时文件有 128 MiB 监测阈值，每 100 毫秒检查一次；可能有一个检查间隔的增量。超限会取消进程并明确失败，不静默截断。正常退出清理文件。临时文件不是跨实例回收的持久检查点。

上传批次最多 2000 条、约 2 MiB；内存队列同时限制条数与序列化字节量。PostgreSQL 使用 COPY 入库，保留批次序号、内容哈希、执行版本和完成凭证。

## 高开放率目标

原始端口观测不设置 512 / 1024 条截断。超过 1024 个开放端口时，后续指纹优先选择常见端口，再均匀采样补足最多 1024 个。页面显示“指纹受限”，其余端口仍可查看。

原始观测当前仍按行保存。整个网段全开放时，需要结合存储和入库吞吐评估容量；当前尚未完成密集位图、网段自动熔断和自动归档。

## 取消、回收与重试

心跳携带停止任务列表，续约返回停止动作。Agent 取消执行并终止扫描进程组；无法联系平台时，60 秒发包许可到期是独立兜底。执行、上传及完成确认共同受 180 秒上限约束。

ECS 中断事件、metadata 和租约失效各自承担通知或失联兜底职责。重新认领增加 `attempt_no`，旧执行的新批次被拒绝，已提交且内容相同的批次可以确认已有凭证。查询只计算当前执行版本。

确定性执行超时最多尝试 3 次；实例回收和基础设施故障不扣减该超时预算。临时文件超限等不可重试错误直接失败。

## 验证边界

`deploy/load-fixture.sh` 在显式启用时创建隔离网络命名空间，提供逻辑 IP、全开放目标和延迟响应。它可以验证执行、调度、回传和数据完整性，不等于独立公网主机的 RTT、丢包与防火墙分布。合成产品标记不是相应软件真实安装的证据。

更高速率配置、混合负载和大量 Worker 的长期性能需要独立测量。当前不提供百万 IP / 天等容量承诺。

## 可选 PoC 阶段

PoC 不改变 TCP 1–65535 的覆盖范围及开放端口保留策略。只有创建任务时显式选择只读检查，当前执行版本的 HTTP 响应完成提交后，才按“来源目标、同源 HTTP 端点、所选规则”派生 PoC 任务。同源以 scheme / host / port 判断；HTTP 重定向到其他源时不自动扩大 PoC 范围。规则来自任务快照，按规则逐项调度和入库。

每 Worker 最多执行一个 PoC（包括 Nuclei）；原生检查 60 秒，Nuclei 90 秒，仍受任务租约、取消和总截止控制。单规则至多 3 个 GET / HEAD 请求；Nuclei 并发和速率受执行器约束。取消时杀掉独立进程组；租约及 attempt fence 与其他任务相同。探测超时、缺少执行引擎、无有效输出、响应不完整均记录为检测错误，不记为未命中。
